An **AI-driven matching decompilation with human review** of **Super Mario 3D World + Bowser's Fury**
(Nintendo Switch, 1.0.0).

This project is a proof of concept: can AI agents, guided and reviewed by a human,
make a decompilation of this scale practical? Switch games contain enough code to make
complete decompilation an enormous undertaking for a single person. AI agents perform
much of the reconstruction, matching, and documentation work, with human direction and
periodic review.

Each translation unit is rebuilt from C/C++ with the game's own compiler (Clang for NX 1.8.14)
and compared against the original code with [objdiff](https://github.com/encounter/objdiff).
Matching progress measures the reconstructed code; it does not imply that every change
has received human review.

This is a solo project. **Pull requests and outside contributions are not accepted.**
The repository is being made public so others can browse the reconstructed game code
and its libraries, and follow the experiment's progress.

Building
--------

```sh
python configure.py   # config/1.0.0/* -> build.ninja + objdiff.json
ninja                  # units that have source
ninja all              # every unit (needed for the progress report)
python tools/progress.py
```

Requirements: Python 3.10+ with `pyelftools`, `capstone`, `lz4`; ninja; the NintendoSDK
compiler in `tools/nnsdk/`; objdiff-cli in `tools/bin/`; `fury.nso` in the repository root.
On Linux/macOS the SDK compiler runs under wine.

Progress reports
----------------

`python tools/progress.py` builds the project, measures progress with objdiff, updates the
README table, and exports the checked-in `report.json`. The report contains per-function,
per-file, and per-library measurements for game version `1.0.0`.

On pushes to `main`, the **Update Progress** GitHub Actions workflow validates this snapshot
and uploads `report.json` as the `1.0.0_report` artifact for
[decomp.dev](https://decomp.dev). CI publishes the locally measured snapshot; it does not
rebuild the game. [The decomp.dev project page][progress_link] tracks these uploaded reports
and supplies the Code and Data badges and the visualization above.

Enable the local hook to refresh and stage both the README and report on each commit:

```sh
git config core.hooksPath tools/hooks
```

If you skip the hook with `SKIP_PROGRESS=1`, regenerate and commit the report before
publishing code changes so the snapshot stays current.

Commit the generated `report-metadata.json` alongside `report.json`. CI checks its source
and report fingerprints and fails if the snapshot is stale; it never rebuilds the game.
